1. QUÉ HACE CADA ARCHIVO
================================================================

Register.jsx  -> La pantalla de registro: los campos del formulario,
                 la validación, los mensajes y el guardado de usuarios
                 en localStorage.
Register.css  -> Los estilos (colores, tamaños, bordes) de esa pantalla.
index.css     -> Estilos globales. Aquí está el fondo compartido:
                 el sol, el suelo y la rejilla animada.
App.jsx       -> Decide qué pantalla se muestra: Home o Register.
Home.jsx      -> Se le añade la posibilidad de avisar al pulsar "Empezar".
Buttons.jsx   -> El botón "Empezar" ahora acepta una función onClick.

Flujo:
  Home  --(clic en "Empezar")-->  Register
  Register --(clic en "Volver al inicio")-->  Home

Los usuarios se guardan en localStorage (el navegador). Al recargar la
página siguen ahí, pero solo en ese navegador. No es una base de datos
real: sirve para practicar.

El fondo (sol + suelo + rejilla) estaba dentro de Home.css. Ahora vive
en index.css para que Home y Register usen exactamente el mismo.

3.5 src/index.css (fondo compartido)
================================================================

Este archivo se importa una sola vez en main.jsx, así que sus estilos
se aplican a TODA la aplicación. Por eso Home y Register comparten el
mismo fondo.

L1-L5    *, *::before, *::after { box-sizing: border-box; }
         Hace que el padding y el borde se cuenten dentro del ancho
         de los elementos. Es una base cómoda para maquetar.

L7-L12   body { ... }
         Quita el margen del navegador, pone la fuente general,
         el fondo verde oscuro y el color de texto claro.

L14      /* Fondo compartido por Home y Register */
         Comentario que indica que lo siguiente es el fondo común.

L15-L23  .suelo { ... }
         Caja del suelo: position: absolute la pega abajo, ocupa el
         50% de la altura y activa perspective: 400px para dar
         sensación de profundidad a la rejilla. Además, pointer-events:
         none hace que el fondo NO capture los clics del ratón.

L25-L39  .rejilla { ... }
         Dibuja la cuadrícula verde:
         - background-image: dos linear-gradient (líneas horizontales
           y verticales).
         - background-size: 50px 50px (tamaño de cada celda).
         - transform: rotateX(60deg) la tumba para simular un suelo 3D.
         - opacity: 0.4 la hace semitransparente.
         - animation: mover-rejilla 2s linear infinite la anima sin fin.

L41-L48  @keyframes mover-rejilla { ... }
         Define la animación: mueve el fondo de 0 a 50px en vertical.
         Como el bucle es infinito, parece que la rejilla avanza.

L50-L60  .sol { ... }
         El sol: un círculo amarillo de 250x250 px colocado con
         position: absolute arriba a la derecha, con un resplandor
         (box-shadow). También tiene pointer-events: none para que no
         bloquee los clics.

NOTA: el suelo y el sol se colocan respecto al contenedor más cercano
que tenga position: relative. En Home es .hero y en Register es
.registro. Por eso ambos tienen position: relative.

Qué probar:
  1. En Home, pulsa "Empezar" -> debe aparecer la pantalla de registro.
     El botón "Empezar" debe verse del mismo tamaño que antes.
  2. La pantalla de registro debe tener el mismo fondo que Home:

8. CONCEPTOS CLAVE EXPLICADOS
================================================================

useState
  Guarda un dato que puede cambiar y hace que la pantalla se actualice
  cuando cambia. Se usa así:
      const [valor, setValor] = useState(valorInicial)

Componente controlado
  El input no guarda su texto por su cuenta: su value viene del estado
  y su onChange actualiza el estado. React siempre manda.

onChange
  Evento que se dispara cada vez que el usuario escribe en un campo.
  e.target es el campo, y e.target.value es el texto que contiene.

preventDefault()
  Cancela el comportamiento por defecto del navegador. En un formulario,
  evita que la página se recargue al enviar.

Props
  Datos o funciones que un componente padre pasa a un hijo.
  Ejemplo: App pasa onVolver a Register y onRegister a Home.

className
  En React se escribe className en vez de class, porque class es una
  palabra reservada de JavaScript.

htmlFor
  En React se escribe htmlFor en vez de for, por la misma razón.

Condicional con &&
  {mensaje && <p>...</p>} muestra el <p> solo si mensaje tiene texto.

type="button" vs type="submit"
  submit envía el formulario (dispara onSubmit).
  button solo ejecuta su onClick. El botón "Volver" debe ser button
  para no enviar el formulario sin querer.

Función flecha
  Forma corta de escribir una función:
      () => setPantalla('home')
  Se usa mucho para pasar funciones como props sin ejecutarlas en el
  momento.

localStorage
  Un pequeño almacén que el navegador guarda en el disco del usuario.
  Solo puede guardar TEXTO (strings), y los datos no caducan solos.
  - localStorage.setItem('clave', 'valor')  -> guardar
  - localStorage.getItem('clave')           -> leer (o null)
  - localStorage.removeItem('clave')        -> borrar
  Los datos son visibles y editables desde DevTools, así que no sirven
  para guardar contraseñas reales.

JSON.stringify / JSON.parse
  Son conversiones entre objetos de JavaScript y texto.
  - JSON.stringify(array) -> texto (para guardar en localStorage)
  - JSON.parse(texto)     -> array u objeto (para volver a usarlo)
  Ejemplo:
      const texto = JSON.stringify([{ nombre: 'Ana' }])
      const datos = JSON.parse(texto)

Array y .push()
  Un array es una lista. push(...) añade un elemento al final:
      const lista = []
      lista.push('Ana')   // lista ahora es ['Ana']

.some()
  Recorre un array y devuelve true si ALGUNO de sus elementos cumple
  una condición:
      const hayAdultos = edades.some((edad) => edad >= 18)

Operador ||
  Se usa como "si lo de la izquierda es null/vacío, usa lo de la
  derecha":
      const lista = JSON.parse(...) || []
  Si getItem devuelve null, nos quedamos con un array vacío.

position: relative / absolute
  position: relative deja el elemento en su sitio, pero además lo
  convierte en la REFERENCIA para sus hijos absolutos.
  position: absolute saca el elemento del flujo normal y lo coloca
  usando top/right/bottom/left respecto a su contenedor relativo.
  Ejemplo: .registro es relative y .sol es absolute, así el sol se
  coloca arriba a la derecha de la sección, no de la página.

overflow: hidden
  Recorta todo lo que sobresalga del elemento. Se usa para que la
  rejilla (que mide el 200% de ancho) no cree scroll horizontal.

Selector descendiente (.tarjeta .boton)
  Aplica estilos solo a los elementos que están dentro de otro.
  Permite tener dos botones con la misma clase .boton y que cada uno
  se vea distinto según dónde esté.

z-index
  Controla qué elemento queda encima cuando se solapan.
  La tarjeta tiene z-index: 1 y position: relative, así queda por
  encima del sol y de la rejilla.

pointer-events: none
  Hace que un elemento sea "transparente" a los clics: el ratón lo
  atraviesa y llega a lo que hay debajo. Perfecto para decoración
  como el sol o la rejilla.
